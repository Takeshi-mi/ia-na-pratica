O que eu faria

Começar pela planilha exportada. O banco de dados fica para quando as perguntas estiverem claras

A primeira versão não precisa de acesso ao banco: exporte vendas e despesas em planilha, entregue para a IA e faça as perguntas que hoje viram relatório manual. Em uma tarde dá para saber quais perguntas importam e se a IA acerta os números.

Depois vem o que faz a IA acertar de verdade: um dicionário de dados (o que é cada tabela, coluna e regra do negócio) e um usuário só de leitura no banco. Com isso, a pergunta em português vira SQL, o SQL roda e a resposta vem com o número e a conta. É o que o protótipo abaixo faz.

Para quem programa · a versão conectadaCodexClaude Code


Crie um “pergunte aos dados” interno em [Python + FastAPI].

- Conecte no banco [PostgreSQL] com um usuário SOMENTE LEITURA, restrito às views vendas, metas, despesas e orcamento.
- A pergunta em português vira SQL usando o dicionário de dados em dicionario.yaml. Mostre o SQL junto com a resposta.
- Bloqueie qualquer comando que não seja SELECT, aplique LIMIT e timeout de 10 s e registre em log quem perguntou o quê.

    Cuidados
    
O que costuma dar errado

  

  
    
    
  • Só leitura, sempre. A IA nunca recebe permissão de alterar, apagar ou criar dados no banco da empresa.
    • 
    
  • LGPD. Dado pessoal de cliente e funcionário fica fora ou mascarado. Use a conta corporativa aprovada pela empresa.
    • 
    
  • Confira os números. Antes de confiar, compare com um relatório que já existe. Peça sempre o SQL ou a conta.
    • 
    
  • Regras do negócio. Venda é pedido ou faturamento? Despesa entra pela data da nota ou do pagamento? Sem dicionário, a IA chuta.
    • 
    
  • Quem vê o quê. As permissões do banco valem para a IA: vendedor não deve ver despesa da diretoria só porque perguntou.
    • 
    
  • Consulta grande custa. Limite linhas e tempo de cada consulta, para não pesar no sistema que a empresa usa para vender.
